# V42 — sandbox payment event ledger
Candidate backend only. Stripe snapshot webhooks must have a valid raw-body HMAC signature (five-minute timestamp tolerance). Only test events, test keys and six specified event types; current subscription state retrieved from Stripe. Each event ID is unique in the service-only append-only table. No raw webhook payloads, card details, or production entitlements are stored. Event delivery order is not trusted; these records are observations, not a latest-state ledger or a source of paid access. No access is granted by the endpoint. Future V43 requires independently reconciled current state, ownership/customer mapping, unique active subscription and quota enforcement. SQL candidate under billing/ is not applied; database ACL tests and real Stripe event tests are required before activation. Separate webhook enable flag defaults off. Stripe endpoint will use snapshot events and signing secret, not Supabase user JWT (Stripe cannot supply one). Do not disable JWT verification on any other function. For development, keep SELLERPILOT_STRIPE_ENABLED=false. Docs: https://docs.stripe.com/webhooks ; https://docs.stripe.com/changelog/basil/2025-03-31/deprecate-subscription-current-period-start-and-end .
