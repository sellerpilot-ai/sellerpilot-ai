# V48 sandbox checkout — request-level Managed Payments opt-out
Stripe returned HTTP 400 after the V47 migration: the account enables Managed Payments by default, which conflicts with allowed_payment_method_types. The Stripe API error explicitly recommends passing managed_payments[enabled]=false or removing the filter. V48 uses the per-request opt-out, retaining card-only filtering, fixed GBP price validation, private tester authentication, test-only key/session checks and no entitlement grants. The V48 idempotency namespace avoids replaying the known V47 failure, while repeated V48 requests with the same request ID remain idempotent. No account-wide settings, secrets, live mode, payment provider key, or production merchant-of-record choice changed. Test with the existing dedicated checkout page after successful CI and backend deployment. The exact account-specific fix is based on the provider response supplied by the operator; public indexed documentation does not independently establish the November 2026 API behavior.
