- All six application tables inspected have RLS. Anonymous grants absent for read and write; four server-only tables deny authenticated read/write. Both user tables have owner-only select/insert/update/delete policies, with update USING and WITH CHECK.
- Under authenticated Postgres role and the existing owner's simulated JWT sub, four products and one workspace visible. Under a distinct synthetic sub, zero products and zero workspaces visible.

No real second auth identity or second browser session was created.

2. Sign in with both accounts in independent browser contexts. Add one fictional listing and research note to each. Through the normal authenticated API verify own CRUD succeeds; cross-account read, modify, delete and owner impersonation fail in both directions for products and saved workspace. Verify anonymous access fails. Sign out and verify no prior private data remains.
3. Verify invitation/password recovery emails, authorized redirects, password settings and server-side signup restriction.
4. Review actual AI secret configuration in dashboard (no secret value in chat).
