# V44 — private sandbox billing portal candidate
Uses existing verified private test account and service-only ledger lookup, never browser-supplied customer ID. Requires one unique recorded customer; rejects shared recorded customers, mixed subscription ownership or incomplete provider list. Checks a dedicated active sandbox portal configuration: invoice history, payment method changes and end-of-period cancellation on; proration none; plan changes, customer-detail updates and public login off. Stripe-hosted test URL, fixed return. No live keys, direct billing mutations beyond creating a temporary test portal session, or access grants. Existing private beta remains unchanged. Requires actual V42 ledger, V44 SQL permissions, webhook and sandbox configuration, and a real test customer. Ledger ownership is a candidate for private testing only; production needs dedicated immutable customer mapping, full lifecycle reconciliation, invoice scope/ownership review and race-condition handling. No upgrades/downgrades, live renewals, refund or dispute handling implemented by this module. Environment SELLERPILOT_STRIPE_PORTAL_ENABLED defaults off; SELLERPILOT_STRIPE_PORTAL_CONFIG is a sandbox bpc_ ID. All SQL and endpoints remain undeployed until V45. Docs https://docs.stripe.com/customer-management/integrate-customer-portal and https://docs.stripe.com/api/customer_portal/sessions/create .
